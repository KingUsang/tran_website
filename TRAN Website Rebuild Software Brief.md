##### **1. Executive Summary** 

The current TRAN website is structurally functional, but it no longer represents the company TRAN is becoming. The biggest issue is not visual polish; it is positioning. The live homepage currently leads with Ubuntu Bridge Initiative, describes TRAN around “Community · Mentorship · Education”, and the footer calls TRAN a cybersecurity education company. The Programs page also presents CYTRAC, mentorship, webinars, street outreach, UBI and other activities as parallel programmes. That architecture conflicts with the new strategy: TRAN is the parent Educational IP company; CYTRAC™ is the flagship commercial IP; Ubuntu Bridge Initiative (UBI) is the social-impact arm. 

The rebuild should therefore feel less like a community programme website and more like a modern educational entertainment/IP company: credible enough for investors and partners, emotionally engaging enough for parents and schools, and simple enough that a visitor understands the company structure within five seconds. 

### **Top priorities** 

- Reposition TRAN clearly as an Educational Intellectual Property company — not a cybersecurity training company. 

- Make CYTRAC™ the primary commercial story and give it the strongest visual prominence. 

- Position UBI clearly as TRAN’s social-impact arm, with its own identity and pathway. 

- Reduce the number of equal-weight “programmes”; create a parent-brand → flagship-IP → social-impact hierarchy. 

- Design the site around clear audiences: parents/schools, partners/investors, media, and social-impact supporters. 

- Use stronger storytelling, product visuals, impact proof, and conversion-focused calls to action. 

- Build a modular CMS so TRAN can add future IP, books, animation, school resources, licensing and press without redesigning the site.

## **6. Page-by-Page Developer Brief** 

### **6.1 Home Page** 

Goal: Explain TRAN in five seconds, create emotional interest, establish credibility, and route visitors to CYTRAC, UBI or partnership. 

- Hero: Strong visual of children/families interacting with CYTRAC or a polished educational-IP visual universe. Avoid generic hacker imagery. 

- Hero eyebrow: “Educational Intellectual Property for a safer digital generation.” 

- Hero headline example: “We build worlds that help children play, learn and stay safer online.” 

- Hero subcopy: “The Root Access Network creates educational IP that turns digital-safety lessons into games, stories and experiences children actually want to engage with.” 

- Primary CTA: “Explore CYTRAC™”. Secondary CTA: “Our Story” or “Partner With Us”. 

- Brand architecture block: TRAN → CYTRAC (commercial) + UBI (social impact). This can be a simple two-card visual. 

- Flagship IP section: large CYTRAC product/character visuals, tagline “Play. Learn. Stay Secure.”, concise explanation and CTA to CYTRAC website/product page.

### **Design system recommendation** 

- TRAN: sophisticated parent-brand palette; use dark/neutral foundation with one distinctive brand accent. 

- CYTRAC: brighter, playful, children-friendly colour system and character/product imagery. 

- UBI: dark navy + purple + white; green only as a supporting Ubuntu accent. 

- Use one consistent typography family or a carefully paired display/body system. 

- Use an 8pt spacing system, reusable cards, CTA styles, content widths and responsive breakpoints. 

- Motion should be purposeful: subtle hover states, product reveals, scrolling ecosystem journey; respect reducedmotion preferences.

## **9. Technical, SEO & Accessibility Requirements** 

### **Performance** 

- Target Google Core Web Vitals: LCP ≤ 2.5s, INP < 200ms and CLS < 0.1 on the 75th percentile of real users. 

- Optimise WebP/AVIF images, responsive srcset, lazy-load below-fold media, and avoid autoplay-heavy hero video on mobile. 

- Minimise third-party scripts and animation libraries; defer non-critical JavaScript. 

- Use CDN/caching, compressed assets and server-side/static rendering where appropriate. 

### **Accessibility** 

- Target WCAG 2.2 AA. 

- Semantic headings in correct hierarchy, landmarks, visible keyboard focus and skip-to-content link. 

- All interactive elements keyboard operable; minimum target sizes and sufficient contrast. 

- Meaningful alt text for product/impact images; decorative images should have empty alt. 

- Caption/transcript all important video content. 

- Forms: labels, error messages, autocomplete, clear success states and accessible authentication/spam protection. 

- Respect prefers-reduced-motion. 

### **SEO / structured data** 

- Unique title/meta description for every page; clean canonical URLs. 

- Organisation schema for TRAN; Product/Offer schema for CYTRAC commerce pages; Event schema for launches/webinars where appropriate; VideoObject for key videos. 

- Open Graph/Twitter social metadata with intentional images. 

- XML sitemap, robots.txt, Search Console and analytics configured. 

- Redirect legacy programme URLs to the most relevant new destination to preserve link equity. 

- Build pages around search intent such as children’s online safety, digital safety board game, online safety for schools, cybersecurity education for children — but keep copy human-first. 

### **Security / privacy** 

- HTTPS, secure headers, dependency/plugin patching and least-privilege CMS accounts. 

- Protect forms from abuse, sanitise inputs and avoid exposing admin endpoints unnecessarily. 

- Cookie/analytics consent appropriate to UK/EU visitors; privacy policy and retention rules for enquiry/newsletter data. 

- Backups, restore testing, uptime monitoring and documented content deployment/rollback process.

## **14. Recommended Design/Development Workflow** 

1. Discovery: confirm brand architecture, active programmes, URLs, conversion goals and assets. 

2. Content inventory: mark every existing page/section Keep / Rewrite / Move / Retire. 

3. Wireframes: desktop + mobile for Home, CYTRAC and Partner pages first. 

4. Visual direction: approve one homepage design before styling all templates. 

5. Build design system/components, then pages. 

6. Populate real content early; do not wait until the end with placeholder text. 

7. QA: mobile, accessibility, forms, performance, redirects, metadata, analytics. 

8. Soft launch/staging review with founder + 3 representative users (parent, school/partner, tech/community user). 

9. Launch, then review behaviour data after 30 days and iterate.
